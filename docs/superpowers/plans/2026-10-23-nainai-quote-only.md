# NaiNai Two-Case Quote-Only Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let one buyer research, negotiate and review quote/findings packets for a real table need and an explicitly evaluation-only GPU scenario, without purchasing anything.

**Architecture:** One TypeScript app/server and SQLite database, one bounded agent coordinator, two typed category adapters. Application code enforces contact permissions, evidence provenance, calculations and immutable review revisions; model output proposes actions and extracted terms. No purchasing or compute-provisioning capability exists.

**Tech Stack:** Proposed defaults: React/Vite, an established component kit, Express, TypeScript, Zod, SQLite, decimal.js, Vitest and Playwright. Pin compatible supported versions during event setup; nothing is installed by this plan.

**Spec:** [Current quote-only MVP](../specs/2026-10-23-nainai-quote-only-mvp-design.md). [Presenter script](../../NAINAI_DEMO.md). These supersede the earlier single-category purchase-approval/reservation plan. Planning only; implementation begins during the official event period and only when requested.

The later Grandma's Receipt, next-step advisor, judge challenge enhancements, alternative projects, new backends and additional sponsors remain proposals, not implementation requirements. No application, dependencies, accounts or supplier conversations have been created by this planning revision. [Acceptance matrix and readiness](../../NAINAI_RELIABILITY.md).

- No silent redial/follow-up/cross-channel retry; refusal/opt-out is terminal without fresh appropriate authority. Pause prevents queued/future actions; explicit stop ends the active conversation. AI/transcription/recording/public sharing permissions are separate.
- Original sources, timestamps, scope, intent, evidence origin, uncertainties and permissions survive export. Public listings and extracted transcript proposals are not confirmed quotes. No paid/fulfilled savings claim.
- Five conditional program targets: Visa, Cartesia, Microsoft, Apify, Figma. Hyphenate deferred. No eligibility or measured outcomes earned yet; second submission deferred.
- One server process owns SQLite and external dispatch. Store mutable runtime data in an unsynced local directory (`NAINAI_DATA_DIR`, default `%LOCALAPPDATA%/NaiNai/cal-hacks` on Windows), not the OneDrive checkout; tests use temporary directories. No background worker infrastructure or distributed queue.
- Node 24 LTS is the default runtime; pin exact compatible package versions and commit the lockfile during Task 1. Run a SQLite persistence smoke before parallel integration; do not defer native-binding/setup failures until the demo. The binding choice is the lead's routine implementation decision, recorded with the smoke result.

## Review Focus

1. Supplier instructions or redirect URLs try to obtain secrets or invoke purchasing: treat content as data, enforce tool/network allowlists (Tasks 2/3).
2. A low GPU rate hides a longer minimum term or tiny fractional rate: decimal-safe full-commitment calculation, unknown extras remain unknown (Task 2).
3. Quote/permission revision changes during duplicate review or contact dispatch: atomic current-revision checks; one review per snapshot; revoked contact cannot dispatch; null-quote reviews also deduplicate (Tasks 1/3).
4. A real supplier answers an evaluation request: preserve authentic origin and evaluation intent independently; no invented company/workload or reserved capacity (Tasks 2/3/4).
5. Network ambiguity, restart or duplicate/out-of-order callbacks: preserve unknown delivery, never redial automatically, never reactivate a stopped session, and never turn a network failure into supplier refusal/no response. Missing fees, expiry, changed condition and withdrawn permission remain visible (Tasks 1/2/3/4/5).

**Interfaces:** Freeze Zod schemas and inferred types in `contracts.ts` before dispatch:
- `CaseRequest` is a discriminated union keyed by `category: 'table' | 'gpu'`; both carry `caseId`, `requestRevision`, `intent`, `requirements`, `capCents`, `capMode`, assumption origins. Bind table to `actual_need`, GPU to `evaluation_only`.
- `EvidenceRef` carries ID/revision, case/intent, origin (`public_observation | supplier_artifact | conversation_proposal | synthetic_fixture`), supplier ID, source/provider/run/channel, timestamp, original artifact hash/excerpt, scope, expiry, permissions and verification status.
- `QuoteSnapshot` carries quote ID/revision, case/intent, requirements, decimal-string rate inputs, known/included/unknown cost components, total in integer cents or null, evidence refs, confirmation status and scope key.
- `Assessment` contains `outcome` (`qualifying_table_quote | no_qualifying_offer | needs_clarification | evaluation_findings | declined | no_response`), requirement checks, unknowns, total/commitment, confirmation and comparable-scope status.
- `PacketSnapshot` contains case, nullable quote, evidence, assessment and exact request/quote/evidence/permission revision tuple. `ReviewRecord` stores ID, buyer ID, timestamp and immutable packet snapshot; no commercial status. Store protected artifact references, not copied audio/secrets. Current access/sharing permissions govern every later display/export, including old reviews; redact withdrawn assets/excerpts while retaining permissible metadata. Previously downloaded copies cannot be recalled.
- `SessionState` contains session ID, case/supplier IDs, status (`pending | active | ended | failed`), control (`ai | human`), provider IDs and permission revision. `CampaignState` contains pause/cancellation revisions, jobs (ID, case, kind, status, timestamps, error), sessions and separately measured research/contact/reply/confirmed counts. `AssessmentContext` contains conversation outcome (`pending | declined | no_response | failed | complete`) and reason; actual session events establish it, not quote absence alone.
- `loadPacket(caseId: string): Promise<PacketSnapshot>`; `reviewQuotePacket(input: {caseId: string; expectedRevisions: PacketSnapshot['revisions']; idempotencyKey: string}, buyerId: string): Promise<ReviewRecord>`; `exportPacket(reviewId: string, buyerId: string): Promise<string>` (JSON download with labels/unknowns).
- `ToolAction` is a discriminated union with common `caseId`, `requestRevision`, `permissionRevision`, `idempotencyKey`. Branches: `{kind:'research'; sourceIds:string[]}`, `{kind:'request_quote'; supplierId:string; endpointId:string; sessionId:string|null; purpose:'initial_quote'|'counterproposal'; text:string}`, `{kind:'record_proposal'; supplierId:string; sessionId:string; quote:QuoteSnapshot}`, `{kind:'stop_session'; sessionId:string}`. Endpoint IDs resolve only to authorized canonical endpoints; source IDs resolve to allowed public sources. `authorizeTool(action: ToolAction, buyerId: string): Promise<void>` checks stored intent, scope, limits and revisions immediately before effects. Purchasing/provisioning is absent; unknown names/fields rejected at runtime.
- `QuoteSessionTools` has `requestQuote(action: Extract<ToolAction,{kind:'request_quote'}>): Promise<{sessionId:string;providerActionId:string}>`, `recordProposal(action: Extract<ToolAction,{kind:'record_proposal'}>): Promise<{quoteId:string;quoteRevision:number}>`, `stopSession(action: Extract<ToolAction,{kind:'stop_session'}>): Promise<void>`. These delegate to the authorized dispatcher; they never confirm their own extracted proposals. Provider callbacks update stored session/job states through authenticated, replay-protected lead handlers.
- Lead freezes `DispatchRecord`: ID, workspace/buyer/case/supplier/endpoint IDs, action kind/purpose, request/permission/cancellation revisions, idempotency key, payload hash, provider action ID or null, timestamps/deadline, and status `prepared | sending | acknowledged | delivery_unknown | failed_before_send | cancelled`. `prepareDispatch(action: Extract<ToolAction,{kind:'request_quote'}>, buyerId: string): Promise<DispatchRecord>` atomically authorizes and records contact intent; `dispatchPrepared(id: string): Promise<DispatchRecord>` rechecks revisions/pause immediately before the provider send. Local proposal recording never uses this external dispatcher; owner-requested termination is a separate control. Release database transactions before network I/O. Do not promise network-side exactly-once delivery.
- Lead freezes `ProviderEvent`: provider name, provider event/session IDs, payload hash and normalized event kind. `ingestProviderEvent(event: ProviderEvent): Promise<'applied' | 'duplicate' | 'ignored'>` accepts only server-authenticated, schema-validated callbacks; provider-specific credentials/signature checks live at the ingress boundary. Bind events to stored session/buyer identity, not IDs asserted by arbitrary callers. `recoverPendingActions(): Promise<void>` runs before dispatch is enabled at startup. Records left `sending` become delivery_unknown and block new external conversations until reconciled; prepared contacts remain paused until explicitly resumed under still-valid authority. Read-only provider status reconciliation never initiates a new call/message.
